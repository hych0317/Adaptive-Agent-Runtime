# 运行停止机制设计

## 1. 目标与状态语义

Runtime Core 对每个 Run 冻结一份 `RunStopPolicy`，并在规划前后、动作执行前后以确定性规则检查停止条件。Agent 可以报告事实，但不能自行修改计数器、预算或最终停止决定。

运行结果区分两类终态：

- `terminated`：命中运行护栏，例如轮数、Token、成本、时间、重复调用或长期无进展。该状态不写入普通 `error`，停止原因保存在结构化 `termination` 中。
- `failed`：任务或关键依赖发生失败。关键工具不可恢复失败同样携带结构化 `termination`，但终态为 `failed`。

每次停止都会保存主原因、同时命中的全部原因、检查阶段、策略指纹、用量快照、证据和触发时间，并产生 `runtime.stop_triggered` 事件。护栏停止随后产生 `runtime.terminated`，失败停止产生 `runtime.failed`。

## 2. 已实现的停止范围

| 范围 | 配置/事实 | 判定时点 | 结果 |
|---|---|---|---|
| 最大轮数 | `max_action_steps` | 动作开始前 | `terminated / max_action_steps` |
| Token 预算 | `max_total_tokens` | 规划前后、动作前后 | `terminated / token_budget_exhausted` |
| 成本预算 | `max_monetary_cost + currency` | 规划前后、动作前后 | `terminated / cost_budget_exhausted` |
| 墙钟期限 | `max_wall_clock_seconds` | 所有 Core 检查点及动作准入 | `terminated / wall_clock_deadline` |
| 活跃执行预算 | `max_active_execution_seconds` | 规划或动作结束后 | `terminated / active_execution_budget` |
| 单次工具超时边界 | `default_tool_timeout_seconds`、`max_tool_timeout_seconds` | 动作规范化与准入 | `terminated / tool_timeout` |
| 外部长任务期限 | `external_job_deadline_seconds` | Job 观测之后 | `terminated / external_job_deadline` |
| 外部长任务心跳丢失 | Job heartbeat + `max_no_progress_seconds` | Job 轮询之后 | `terminated / external_job_heartbeat_lost` |
| 连续重复调用 | `repeated_invocation_limit` | 动作准入和实际 Provider 调用前 | `terminated / repeated_invocation` |
| 连续无进展轮数 | `max_no_progress_steps` | 观测之后 | `terminated / no_progress_steps` |
| 无进展活跃时间 | `max_no_progress_seconds` | 规划之后 | `terminated / no_progress_time` |
| 关键工具不可恢复失败 | 结构化 `FailureDisposition` | 观测或失败规划之后 | `failed / critical_tool_failure` 或 `recovery_exhausted` |
| 用量不可核算 | 缺少权威 Token/成本报告 | 规划之后 | `terminated / usage_accounting_unavailable` |

如果同时命中多个条件，Runtime 按固定优先级选择主原因，同时保留全部匹配原因，避免代码分支顺序改变结果。

## 3. 分层时间控制

### 3.1 墙钟、活跃时间和工具时间

三类时间分别计量：

- 墙钟时间从 Run 创建开始，包含工具等待、外部 Job 等待、进程停机和恢复间隔。默认不启用，只有配置 `max_wall_clock_seconds` 才生效。
- 活跃执行时间累计 Planner 和 ActionExecutor 实际占用的时间，不包含进程停机。
- 单次工具时间由 Action 的 `timeout_seconds` 控制；未声明时，Core 写入策略的默认工具超时。执行器负责落实取消或超时协议。

Core 不用一个短的全局 `asyncio.timeout` 包住整个 Run。启用墙钟期限时，工具开始前必须满足：

```text
剩余墙钟时间 >= 本次工具完整超时 + cleanup_grace_seconds
```

不满足时工具不会启动。满足时，本次调用由自己的超时边界管理；调用返回后 Core 再检查 Run 期限。`cleanup_grace_seconds` 当前用于准入预留，不代表 Core 已实现一个通用的 Provider 清理协议。

### 3.2 长时间外部 Job

提交型工具可以通过 `ObservationControl` 返回 Job ID 和 heartbeat。Runtime 会持久化 Job 开始时间、最近心跳和等待阶段，并分别检查 Job 总期限与心跳丢失。

轮询调用可以使用 `repeat_detection_exempt`，实际 Tool Provider 也可使用 `polling` 标签免除连续重复拦截。有效 heartbeat 会清零通用停滞计数，等待过程仍由 Job 期限约束；重复豁免不影响墙钟、Job 期限、轮数、Token 或成本预算。

### 3.3 无进展时间

工具本身运行很久不会增加“无进展活跃时间”，因此不会仅因工具耗时而被误判为状态停滞。Planner/恢复控制消耗的活跃时间会累计；可信执行器通过 `ProgressKind` 明确报告任务进展、恢复进展或无进展。任务进展和恢复进展都会重置停滞计数。

## 4. Token 与成本的 Run 级核算

LLM Gateway 在 Run 上下文内共享 `RunBudgetLedger`：

1. 请求开始前原子预留剩余 Token/成本，防止并发请求共同超额。
2. Gateway 将单请求上限收紧到本次预留额度。
3. 响应通过契约与单请求预算校验后，提交实际用量。
4. 超额响应按完整预留额度保守记账；缺少已承诺的权威用量时停止 Run，不继续猜测用量。

Run 状态持久化累计用量。恢复时以持久化用量重新创建 Ledger，并校验停止策略指纹相同。

当前只能核算 Backend 返回的权威用量。Provider 在失败响应中不提供计量数据时，Runtime 无法反推真实费用；部署仍应同时设置 Provider 侧限额和 Gateway 单请求重试/时间预算。

## 5. 重复调用与进展判定

重复检测有两层：

- Core Action 层：指纹包含动作名、规范化参数和超时。
- Tool Provider 层：指纹包含 capability、provider 和规范化参数，并在 Provider 产生外部效果前判定。

`request_id`、`call_key`、`trace_id`、时间戳等易变字段不会改变语义指纹，不能通过每轮生成新 ID 绕过检测。不同动作但状态长期无变化时，仍会被无进展轮数或无进展时间规则停止。

进展事实由受信任的执行适配器写入 `ObservationControl`。没有显式标注时，成功观测保守地视为任务进展，失败观测视为无进展，以保持现有执行器兼容。

## 6. 关键失败与恢复

关键失败必须由结构化 `FailureDisposition` 描述：

- `criticality=critical`；
- `retryable=false`；
- `recovery_status=exhausted` 或 `unavailable`。

只有同时满足这些条件，Runtime 才立即形成关键失败终态。普通失败仍可反馈给 Planner 进行重试、换 Provider 或图恢复；最大轮数、重复调用和停滞规则继续为恢复过程提供最终上界。

## 7. 持久化与恢复

以下控制状态随 `AgentState` 一起持久化：策略指纹、墙钟截止时间、活跃时间、累计用量、无进展计数、Action/Tool 指纹、外部 Job 身份和心跳时间。

- 已 `completed`、`failed` 或 `terminated` 的 Run 再次 `resume` 时原样返回，不追加执行。
- 非终态 Run 只能用相同停止策略恢复；策略指纹不一致会拒绝恢复。
- 墙钟截止使用绝对时间，因此进程停机不会重置期限。
- 已开始但结果未知的外部副作用仍遵循原有 in-doubt 保护，不会因恢复而静默重放。
- Planner 因 in-doubt 阻塞恢复时不会推进 Action，但阻塞前已经发生的时间和权威用量仍会保存，防止重启绕过预算。

## 8. 配置示例

```python
from adaptive_agent_runtime import AgentRuntime, RunStopPolicy

runtime = AgentRuntime(
    planner=planner,
    executor=executor,
    state_store=state_store,
    trace_sink=trace_sink,
    stop_policy=RunStopPolicy(
        max_action_steps=32,
        max_total_tokens=100_000,
        max_monetary_cost=5.0,
        currency="USD",
        max_wall_clock_seconds=None,       # 长任务默认不设短全局墙钟
        max_active_execution_seconds=1800,
        default_tool_timeout_seconds=120,
        max_tool_timeout_seconds=900,
        external_job_deadline_seconds=7200,
        cleanup_grace_seconds=15,
        repeated_invocation_limit=3,
        max_no_progress_steps=5,
        max_no_progress_seconds=300,
    ),
)
```
